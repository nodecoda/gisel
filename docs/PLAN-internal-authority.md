# fork 内部权威：凭什么相信 gisel 是对的

状态：**分析 / 计划**，不是产品契约。产品边界见 `docs/SCOPE.md`；对拍本身
属于工作台，不是 gisel 的功能。

本文回答一个问题：在自己的 fork 上，把 `.gisel` 立为规则源、`inc` 作为产物、
官方 C++ 降为参照实现，需要哪些证据才算“我们自己有信心”。

## 0 结论

两阶段思路成立：

1. 接受 `import-cxx` 的初稿，用 gisel 出题对拍官方，证明**接进来的部分没有
   多出/答错**；
2. 再以上游规则区域出题对拍 gisel，证明**上游有的没漏**。

两者合起来是**双向行为等价**，不是“gisel 永远正确”。要把内部权威立住，
还差四件事：U 方向题面、负控、闭包/多步、参照 oracle 保全。

## 1 内部权威的准确定义

> 对某个明确的 fork baseline（commit + patches + feature 配置 + 类型宇宙），
> gisel 的规则表是我们认定的源；`inc` 是它的产物；官方 C++ 是参照实现。

三个限定词不能省：

- **baseline**：pin + patches。patch 变了要重跑，不能继承旧结论。
- **类型/配置宇宙**：结论只覆盖声明域和配置表，不是所有 LLVM 输入。
- **规则表**：只换规则，不换 loop、custom action、memdesc。

在这个定义下，X86 的两条 deviation 不是“问题”，它们就是 fork baseline 的
一部分；但必须在 `PIN.json` / `docs/CORPORA.md` 里点名，否则“权威”会滑成
“gisel 干什么都算对”。

## 2 两阶段证明结构

设：

- `G` = gisel 生成的题面（`cases` + `domain` + 字面量展开）；
- `U` = 上游规则区域生成的题面；
- `Ans_g` / `Ans_u` = 两侧答案函数。

第一阶段：

```text
forall q in G: Ans_g(q) = Ans_u(q)
```

第二阶段：

```text
forall q in U: Ans_g(q) = Ans_u(q)
```

如果 `G` 对 gisel 的答案分区完备，且 `U` 对上游的答案分区完备，那么：

```text
在共同的类型/配置宇宙上：Ans_g = Ans_u
```

这才是“双向包含”。关键在**分区完备**，不是“跑了很多条”。代表点测试在分区
完备时不是抽样，是对商空间的穷举；没有完备性，两个阶段都只是采样。

## 3 第一阶段：证明了什么，没证明什么

准确表述：

> 对 gisel 自己生成的题面 G，官方构建和 include 我们 `inc` 的构建，答案一致。

能抓到：

- gisel 多出来的规则：代表点会被问，官方答 `Unsupported` 或别的动作；
- 动作写错、mutation 写错：等价类代表点和边界点会翻；
- 谓词放宽：多覆盖的区域会被代表点问到。

抓不到：

- 漏规则：`G` 里根本没有那个区域；
- 谓词收窄：看起来就像“漏”，`G` 不会为被排除的点出题；
- 上游独有、且不在 gisel 候选轴/配置表里的区域。

所以“可以漏”是对的。但“没有接进来的没有错误”是空话——没接进来的部分，
第一阶段**不做任何声明**。

“没有扩充题面”也要拆开：

- 指“没有多出规则行为”：在 `G` 上成立，但只在 `G` 覆盖到的配置和类型里成立；
- 指“查询域没有扩大”：这不是第一阶段能证明的，也不需要证明。

## 4 第二阶段：关键不是“上游出题”，是“上游分区完备”

准确表述：

> 对上游生成的题面 U，gisel 的答案与上游一致。

“上游出题”有真假两种做法：

| 做法 | 分母来自 | 性质 |
|---|---|---|
| A6 字面量展开 | `.gisel` 里的字面量（上游 C++ 转录后的字面量） | 转录近似版，仍经过 `import-cxx` |
| 严格上游版 | 官方 `LegalizerInfo` 运行期导出的规则表/谓词 | 不经过 `.gisel`，才是真正上游锚定 |

严格版要成立，需要：

1. 上游侧能导出每条规则的区域和谓词，而不是把 C++ 再转录一遍；
2. 有一个**独立于 gisel 的类型宇宙**；否则 gisel 没想到的类型，上游题面也不会生成；
3. 每个上游等价类至少一个代表点，边界点覆盖答案翻转处；
4. 断言/不可答点不能算 agree。

第 2 条最容易漏。如果 `U` 的类型枚举还是用 gisel 的 `types` 列表，那“上游出题”
只是换了个出题人，宇宙还是 gisel 的，漏掉的类型照样看不见。

## 5 内部权威的五道门

数字是 2026-11-10 快照，会随 axes/feature/规则更新；门禁以命令结果为准。

| 门 | 要求 | 当前状态 |
|---|---|---|
| 参照系 | 明确“对 pin+patches 权威”，deviation 点名 | 有 `PIN.json`；需在权威声明里写清 |
| G 题面 | `domain + cases + 字面量展开`，不只 `cases` | X86 用 `domain` 100,508；AArch64 用 `cases` 10,029；未统一 |
| 分区完备 | 每个等价类有代表点；`unexercised` 规则有交代 | X86 22 / AArch64 396 / RISC-V 82 条未命中（`REPORT-cases`） |
| U 题面 | 上游运行期规则表 + 独立类型宇宙 | 缺 |
| 多步等价 | 闭包通过，或另证“后继封闭 + 终止” | X86 `closure.count=321`，未通过（`REPORT-graph`） |
| 不可答点 | 单列，不混入 agree | X86 1,152 / AArch64 179 条对称断言目前被算进 agree |
| 回归 | getAction 对拍 + `inc` 编译进真实 target + llc/MIR 测试 | getAction 有；全量回归未成门禁 |
| 可复现 | pin 更新自动重跑；产物 sha 固定 | 部分有（`tests/artifacts`） |

## 6 负控：证明对拍有牙齿

这是现在完全缺、但最关键的一环：

> 故意把一条 `legal` 改成 `lower`、把谓词放宽/收窄、删一条规则，重生成 `inc`，
> 重编 ours runner，跑同一份题面——必须报分歧。

如果注入错误后仍然 0 分歧，说明题面在那个区域是盲的，之前的“0 分歧”不可信。
这和 `graph --inject-edge` 是同一个思路：先证明检测器能检测到已知错误。

建议做成一个脚本（工作台，不是 gisel 功能）：

```sh
../ab/inject-rule.py tests/corpus/X86LegalizerInfo.gisel \
  --rule X86_ADD#1 --mutate action=Lower --expect-disagree
```

负控至少要覆盖三类变异：动作翻转、谓词放宽、谓词收窄。每类都要能被抓到。

## 7 换 inc 之后，必须保留 oracle

一旦 fork 的官方 C++ 被 `inc` 替换，**下一次改动就没有官方侧可对了**。

替换前要冻结一份参照：

- 保留原 C++ 构造函数，单独编一个 reference runner，不进入产品；或
- 冻结当前官方答案流 + 构建 sha，作为回归 oracle；
- 每次改 `.gisel`，先对 frozen oracle 跑 `G`/`U` 两套题 + 负控，再进 fork。

没有这一步，“权威”第二年就会退化成“没人记得当初对不对”。

## 8 分 target 授予，不要一次性

| 级别 | 证据 | 现在 |
|---|---|---|
| L0 | 转录 + `inc` 编译 | 有 |
| L1 | `G` 题面对拍 | 有 |
| L2 | 负控注入能被抓 | 缺 |
| L3 | `U` 题面对拍 | 缺 |
| L4 | 闭包/多步 + 全量回归 + frozen oracle + CI | 部分缺 |

“内部权威”应该是 L4 的 target 才授予。X86、AArch64、RISC-V 分别授，不要用
一个总开关。

## 9 权威之后的变更流程

gisel 成为源之后，流程反过来：

1. 改 `.gisel`；
2. 重生成 `inc`；
3. 对 frozen oracle 跑 `G`/`U` 两套题 + 负控；
4. 有分歧先归因：gisel 错就改 gisel；参照实现错就记 issue、保留 gisel；
5. 通过才进 fork。

上游同步也要有策略：要么定期把上游 diff 导入 `.gisel`，要么明确“只跟某个 pin”。
没有策略，漂移会从另一头回来。

## 10 未覆盖 / 边界

- 本文不证明 gisel 对所有 LLVM 输入正确；只对声明域、配置表和 fork baseline。
- 不涉及上游接纳、RFC、社区评审；那是另一个问题。
- 动态 `legalize` 循环的全量等价还没有证据；当前只有一步 `getAction` 对拍，
  闭包未通过。
- `U` 方向尚未实现；A6 字面量展开只是它的转录近似版。

## 11 一句话

> **对明确的 fork baseline，双向题面 + 分区完备 + 负控有效 + 一步能闭包 +
> 保留参照 oracle，才叫我们自己有信心。**

现在有一半（`G` 方向 + 转录 check），缺的是 `U` 方向、负控、闭包和 oracle
保全。把这四件事补上，就可以在 fork 上把 gisel 立为规则源。
